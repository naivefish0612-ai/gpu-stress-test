# Maintainers

This file lists the people responsible for project direction, code review, releases, and governance.

## Core Maintainer

- GitHub: `@naivefish0612-ai`
- Role: Project Lead / Core Maintainer
- Contact: Use GitHub Issues or Pull Requests for normal project discussion.

## Responsibilities

Core maintainers are responsible for:

- Reviewing and merging pull requests.
- Maintaining the project roadmap, issue triage, and release notes.
- Verifying that changes include appropriate tests or manual validation notes.
- Handling security reports and responsible disclosure.
- Maintaining governance, contribution, and ownership files.
- Keeping project discussion clear, respectful, and traceable.

## Permissions

Core maintainers may:

- Merge changes into protected branches.
- Create releases and tags.
- Label, close, reopen, or transfer issues and pull requests.
- Request tests, documentation, or design notes before merging.
- Delay or reject changes that create safety, privacy, legal, or abuse risks.

## Adding Maintainers

A new core maintainer should:

- Have sustained contributions to code, documentation, testing, triage, or releases.
- Communicate technical tradeoffs clearly and respectfully.
- Be nominated by an existing core maintainer.
- Be confirmed after public discussion in an issue or discussion thread.

## Removing Maintainers

Maintainer access may be removed or paused for long inactivity, misuse of permissions, violation of project rules, or safety/security reasons. Decisions should be recorded publicly when possible. Details involving privacy, security incidents, or interpersonal harm may be kept private.

## Decision Principles

Project decisions should prioritize:

1. User and contributor safety.
2. Correctness and maintainability.
3. Clear documentation and repeatable validation.
4. Controlled project scope.
5. Release speed.
